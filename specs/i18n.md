# Languages

The app speaks **English**, **Spanish**, **German**, **French**,
**Portuguese** and **Catalan**. Every text the app writes itself is
translated: screens, buttons, tooltips and screen-reader labels, empty
states, dialogs, snackbars, discipline, gear and grade-system names,
dates ("Sat 17 Oct", "sáb 17 oct") and the
failures the app describes itself (the server took too long, couldn't be
reached, a photo it can't upload, signed out, sign-in failed, couldn't
sign out everywhere). What comes from the server or
from people stays as written: names, bios, places, notes, chat messages
and the server's error messages. A [climbing guide](guides.md)'s text is
in the languages it was written in (the Costa Daurada guide's in Catalan
and English: Catalan for Catalan, English for the rest), under headings
in the app's language. Grades are never translated (6a, 7A+,
5.11c, V5), and times are written 18:30 in every language.

## Picking the language

- By default the app follows the device's language, and English when the
  device's isn't one of the six (for example Japanese).
- **Language** in the [profile editor](screens.md) (at the end) and on the **Profile** tab picks it: **System
  default**, or English, Español, Deutsch, Français, Português (Brasil), Català, each
  named in itself. The whole app switches at once.
- The pick is kept on the device with shared_preferences
  (`grigri.language`, a language code; removed for System default), like
  the [grade system](matching.md), and not sent to the API. A stored code
  this version doesn't speak falls back to System default.
- On the web, `<html lang>` follows the language shown.

## Translation bundles

Flutter's gen-l10n (`flutter_localizations` and `intl`, `generate: true`
in [pubspec.yaml](../grigri_app/pubspec.yaml), settings in
[l10n.yaml](../grigri_app/l10n.yaml)) builds `AppLocalizations` from the
ARB bundles in [grigri_app/lib/l10n/](../grigri_app/lib/l10n):

- `app_en.arb`, the template: every message with an `@key` description
  saying where it shows (and, for headings, that they're shown
  uppercased), and its placeholders.
- `app_es.arb`, `app_de.arb`, `app_fr.arb`, `app_pt.arb`, `app_ca.arb`:
  the same keys, translated. Portuguese is **Brazilian** Portuguese
  (`pt`, whose dates `intl` also writes the Brazilian way). The
  wording is informal (tú, du, tu, você) and uses each language's climbing
  words (vía, búlder and rocódromo; Bouldern and Halle; voie, bloc and
  salle; via, costuras, pico and academia; via, bloc and rocòdrom).
- Counts and names are ICU placeholders and plurals (`{count, plural,
  =1{1 climber} other{{count} climbers}}`, `{yes} of {total} said yes`);
  the discipline in "No sport grades yet" is a `select`, so each language
  phrases it whole.

The generated `app_localizations*.dart` files are committed next to the
bundles and regenerated by `flutter pub get`, `flutter gen-l10n` and
every build. Screens read the texts with `context.l10n`
([lib/ui/l10n.dart](../grigri_app/lib/ui/l10n.dart), which also holds the
enum labels, the language names and the date helpers); the store words
its own messages with the `AppLocalizations` of the language shown, which
the app hands it as the language resolves.

## Keeping the bundles up to date

[test/l10n_test.dart](../grigri_app/test/l10n_test.dart) fails when a
bundle lacks a key of `app_en.arb` or has one it doesn't, when a
message's placeholders differ from the English one, when a template
message has no description or undeclared placeholders, or when the
bundles, the picker's languages and the supported locales disagree (with
English first, as the fallback). It runs with `flutter test`, so the
Release workflow's tests enforce it.

To add or change a text:

1. Add the message to `app_en.arb` with an `@key` description (and its
   placeholders, typed `int` for counts).
2. Add its translation to the other five bundles, in the same change.
3. Use it as `context.l10n.key` (`l.key`) instead of a string literal;
   `flutter test` checks the bundles.

To add a language: add `app_<code>.arb` with every key, and the language,
named in itself, to `languageNames` in `lib/ui/l10n.dart`.
